# Reproducing the pipeline probe

Use a separate checkout of Pulsar fdfc106 and Lightbench f6ccb91. The measured Pulsar runtime source at fdfc106 is unchanged from75b051d; the old release benchmark binary is preserved separately by SHA256. Apply pulsar-instrumentation.patch and lightbench-instrumentation.patch to their matching repositories, then put PhaseTiming.java in Pulsar's com/sumirelabs/pulsar/light package and PulsarTimingBridge.java in Lightbench's com/sumirelabs/lightbench package. Both new files are intentionally separate from the tracked-file patches.

Build both diagnostic copies with JDK25 (`gradlew build`, Lightbench `gradlew spotlessApply build`). The same diagnostic Lightbench binary is used for all three conditions. Conditions are: original Pulsar artifact with `-Dpulsar.phaseTiming=false`; instrumented Pulsar with false; instrumented Pulsar with true. The property must reach the actual relaunched Java25 game process, rather than only the launcher/bootstrap JVM. No extra debug-stat logging or profiler agent is attached.

Follow the frozen environment and commands in the main report and original benchmark protocol. Reset to a fresh copied world and fresh JVM for each condition; repeat all three conditions four times in the specified orders. The fixture, warmup, edit flags and stored-light validators remain unchanged. A result directory contains ordinary Lightbench updates JSON and, when enabled, phase-timing.json. Capture only the default automatic10-worker shared-pool mode. No production configuration field is added by this diagnostic-only patch.

ProbeSelfTest.java can be compiled against the instrumented Pulsar runtime JAR and its Gson dependency. Run it once with `-Dpulsar.phaseTiming=true` and an output JSON path, and once without the flag. It checks concurrent lane aggregation, reset, timestamps, overlap rejection, disabled operation and client exclusion. Existing Pulsar175 and Lightbench60 tests also passed.

For offline analysis, extract diagnostic-raw-data.zip to a study root containing runs/ and manifest-final.json. Place these Python files in tools/ and create progress.json containing `{"status":"measurements-complete"}`. Run analyze.py to revalidate all24 reports and aggregate them. Run plot.py with matplotlib3.11.2/numpy2.5.3 installed. The plot script's local-library fallback is optional; a normal Python environment with those packages also works. package.py additionally expects the two diagnostic checkouts, local probe self-test result and algorithm-comparison.md and is a packaging convenience, not a requirement for rechecking the raw measurements.

The timer source performs no per-cell timestamp or atomic operation. prepare/flood timers are nested in propagation; Sky/Block work and main-thread submission can overlap. Never sum all lane/queue rows as a latency decomposition. Native before-first-task / worker-span / after-last-task intervals are the separate non-overlapping envelope. Probe overhead, wall-time preemption and environmental differences remain limitations described in the main report.
